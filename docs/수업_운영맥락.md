# 수업 운영 맥락

작업을 이어갈 때 읽는 내부 참고 문서다. 교수님 요구의 근거, 현재 연결, 기록 방법과 남은 확인만 유지한다. 이 문서나 점검표를 Notion에 올리지 않는다. 실제 결과·팀 판단·제출물·피드백은 해당 Notion 기록에 남긴다.

## 교수님이 요구하는 방향

작은 실험을 끝까지 실행하고, 조건과 결과를 남긴 뒤 팀 연구에 연결한다. 도구는 규약 → 재사용 지시서 → hooks → 역할 검토 → 실행·기록·알림 자동화 순으로 쌓인다. 설치나 파일 생성만으로 완료 처리하지 않는다.

자료에서 반복되는 기준은 **구체적인 질문과 숫자, 같은 조건의 비교, 실제 출력 확인, 막힌 점과 피드백**이다(W1 9–10·39–42쪽, W3 71–73쪽, W6 68–73쪽, W7 66–69쪽). 높은 성능이나 문서 분량 자체가 목표는 아니다. 연구 질문·해석·다음 계획은 팀이 판단한다.

## 중간발표 후 일괄 제출 안내

근거는 사용자가 전달한 교수님의 중간발표 후 공지다. 기존에 메일·Notion으로 제출한 과제도 최신 판으로 다시 모아, **10/31(토) 23:59까지 팀 대표 1명이 LMS 「팀 과제 일괄 제출」에 제출**한다.

- 제출물: 3주차 문제 정의서, 4주차 데이터 수집 계획서(윤리 체크 포함), 5주차 EDA·전처리 결과, 6주차 기준선 결과(바닥 성능·단순 모델), 9주차 중간보고서, 9주차 발표자료. 여섯 항목 모두 PDF이며 발표자료는 PPTX도 함께 제출할 수 있다. 받은 피드백을 반영한 중간보고서도 허용된다.
- 파일명: `수수컴정_03주차_문제정의서.pdf`처럼 `팀명_주차_항목.pdf`. 수정한 파일은 끝에 `_수정`을 붙인다. 필요하면 `수수컴정_팀과제.zip` 하나로 묶는다. 제출용 파일은 기존 `docs/`에 두고 별도 보존·관리 폴더는 만들지 않는다.
- 5주차는 EDA 그림과 전처리 코드 또는 GitHub 링크를 담은 PDF로 준비한다. 최신 결과 위치는 기존 README의 과제별 표를 따른다. 이전 W5 문서의 1,770/639/591 분할과 삭제된 노트북 경로를 그대로 제출하지 않는다.
- 제출 본문에는 팀명, 팀원 이름·학번·역할, 중간발표자 소지연을 적는다. 연구관리 Notion 링크(실험로그 포함)와 교수 열람 권한을 확인한다. API 연결 성공을 교수 열람 확인으로 간주하지 않는다.
- 아직 확인할 것: 제출용 PDF 여섯 개, W9 Word의 기준선 110→80행 및 반복 일정 W10 반영, 실제 발표 피드백, 팀원 학번, 교수 열람 권한. 실제 LMS 제출 완료는 별도로 확인한다.

## 연결 환경과 기록 순서

- 실습 코드는 수업 루트의 `강의실습/bda-project/`, 팀 연구 코드는 이 레포의 `src/`에 있다. 팀 통합본의 전처리·기준선·PLM 코드와 노트북 두 개를 사용하고, 과거 EDA 실행 구조는 Git 이력으로 확인한다. Windows와 WSL을 구별하고 Python은 WSL Ubuntu-24.04의 `~/envs/research/bin/python`을 사용한다.
- 기존 인증은 WSL `~/.notion_env`: `NOTION_TOKEN` 또는 `NOTION_API_KEY`, `EXPLOG_DB` 또는 `NOTION_DATABASE_ID`. 값은 문서·코드·출력에 남기지 않는다.
- 인증 함수는 [w6_notion_log.py](../../강의실습/bda-project/src/w6_notion_log.py)의 `_credentials()`, 수업 공통 기록 함수는 [notion_log.py](../../강의실습/bda-project/src/notion_log.py)의 `log_experiment()`다. 팀 레포 단독 clone에는 이 실습 폴더가 없으므로 운영 PC의 수업 경로를 확인한다.
- 읽기·쓰기·첨부는 이 기존 API 연결을 우선 사용한다. 플러그인 오류나 Windows 환경변수 공란만으로 연결 불가라고 판단하지 않는다. 새 연결·재인증부터 만들지 말고 실제 HTTP 오류를 확인한다. 최신 REST의 data source ID는 대상 DB 조회로 확인한다.

1. 해당 주차 지시와 실제 출력부터 읽고, **현재 Notion 페이지·속성·첨부를 다시 조회**한다. 제목 변경·삭제 등 사용자 편집을 존중한다.
2. 같은 실행의 보완이면 기존 페이지 ID를 갱신한다. 새로운 실행은 날짜·실행 ID로 구별하고 재시도는 같은 실행으로 취급한다. 제목만으로 중복 행을 만들지 않는다.
3. 속성에 담당·날짜·seed·주요 조건·지표의 단위와 반복 의미를 채우고 논문·데이터를 연결한다. 수행자·읽음 상태·교수 확인·제출 완료를 추측하지 않는다.
4. 본문은 핵심 그림·작은 수치표·짧은 해석 중심으로 쓴다. 한계와 다음 시도는 필요한 만큼만. ‘교수님 지시에 맞게 정리함’ 같은 작업 설명은 쓰지 않는다. 그림 배치는 가독성 원칙이며 모든 주차의 동일한 교수님 양식이라고 부르지 않는다.
5. `결과 파일`에는 실제 PNG·CSV·실행 출력 노트북 등 필요한 자료를 첨부한다. 본문에도 핵심 그림을 넣고 조건·단위·오차막대 의미를 짧게 설명한다. 경로만 나열하지 않는다.
6. 저장 후 수치·관계·첨부·본문 그림·중복 여부를 확인한다. 공통 logger의 `page_id` 재사용만으로 본문·모든 속성이 갱신되지는 않으므로 실제 동작을 확인한다.

- 63쪽 우선순위: 환경 실행 또는 대안 선정 + JSON 가져오기·실제 1회 실행은 필수. **재시도·30분 timeout·고의 실패 알림 확인은 9주차까지.** 58쪽은 실패 후 IF로 넘기기와 날짜·실행 ID로 중복 방지도 요구한다.
- 02:00 예약은 예시다. Publish를 켜 두는 것 자체가 완료 기준은 아니다. 버전은 학기 중 고정하고 업데이트 전 n8n 상태를 백업한다(61–63쪽).
- 현재 경로: [workflow](../../강의실습/bda-project/workflows/w7_nightly.json) → [run_w7.sh](../../강의실습/bda-project/scripts/run_w7.sh) → `w7_ddpm.ipynb` → 공통 logger → 위 W7 실험 행. 시작 명령·설정은 [실습 연결 안내](../../강의실습/bda-project/docs/w7_claude_handoff.md), 세부 실행 근거는 [W7 실습 기록](../../강의실습/bda-project/docs/w7_practice.md)에 있다.
- 저장된 실행 `w7-4`는 노트북·Notion 기록·성공 알림까지 완료했다. 생성된 중복 행은 정리되어 receipt의 이전 페이지와 현재 정리본 ID가 다르다. 실행 근거는 `강의실습/bda-project/results/w7_runs/w7-4/`에 있다.
- 실패·재시도는 smoke 워크플로 `w7-2/3`에서 확인했다. **실제 nightly 워크플로의 고의 실패 알림 시험은 아직 확인되지 않았다.** 저장된 workflow는 비활성이며, 서버가 현재 실행 중인지는 작업할 때 조회한다.
- 수업 자료에는 별도 ‘수업 진행 점검’ Notion 페이지나 n8n 장문 보고서를 만들라는 지시가 없다. 실행 결과와 필요한 짧은 관찰은 실험 행에, 유지·연결 맥락은 이 문서에 둔다.

## 이어서 확인할 것

| 항목 | 현재 경계·다음 확인 |
|---|---|
| 자동 기록 | W3 노트북에는 기록 셀이 없다. W4의 과거 인증 실패 셀을 공통 logger와 대조한다. 팀 baseline의 atexit는 실험 표 한 행을 콘솔에 출력하며 Notion에 전송하지 않는다. 사후 Notion 보완을 자동 기록 성공으로 바꾸어 적지 않는다. |
| 재사용·공유 | W4 새 세션 호출 결과, W6 검토 역할의 팀 Git 공유, 다른 팀원 hook 설치는 확인이 필요하다. 로컬 파일·커밋만으로 공유 완료라고 하지 않는다. |
| n8n | 실제 nightly 워크플로 고의 실패·알림 시험을 9주차까지 확인한다. smoke 시험과 구별한다. |
| 반복 설계 | 팀 baseline은 seed42의 5-fold. W6의 5seed와 다르다. 현재 팀 설계는 유지하고 차이·이유를 설명한다. W10의 3seed는 다음 계획이다. |
| 미확인 사실 | W3 원실행일, GPT-1 읽음 상태, 교수 확인, 링크 제출·리허설은 근거가 있을 때 갱신한다. |
| 피드백 | 다른 팀 질문·제안과 받은 피드백을 해당 연구 기록에 남기고, W10 반영 사항을 연결한다. |

새 주차가 오면 시작 안내·실습·도구 체크·프로젝트·다음 주 지시를 읽고 변경된 요구와 근거 쪽수만 갱신한다. 완료된 남은 확인은 삭제하거나 관련 실제 기록 링크로 대체한다. 수치·그림·회의 규약을 이곳에 중복 복사하거나 점검 문서를 주차별로 늘리지 않는다.
